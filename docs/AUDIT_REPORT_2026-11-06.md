## ปัญหาร้ายแรง (ทดสอบยิง API จริงบนเครื่องแล้ว ยืนยันว่าเกิดขึ้นจริง)

1. **อัปโหลดรูปอะไรก็ได้ ออเดอร์จะเปลี่ยนเป็น "ชำระแล้ว" ทันที** (`src/app/api/verify-slip/route.ts`)
   ในโหมดฟรี (ไม่ได้ตั้ง `EASYSLIP_API_KEY`) ระบบไม่ตรวจยอดเงินและไม่ตรวจว่าเป็นสลิปจริง ทดสอบโดยส่งข้อมูลสุ่ม 64 ไบต์ ออเดอร์ก็เปลี่ยนเป็น `PAID`
   และถ้าเรียก EasySlip ไม่สำเร็จ ระบบก็ปล่อยผ่านเหมือนกัน (fail-open)
2. **ลูกค้ากำหนดราคาเองได้** (`src/app/api/orders/route.ts`)
   ระบบรับ `totalAmount` และข้อมูลสินค้าที่ฝั่งเบราว์เซอร์ส่งมาโดยไม่ตรวจซ้ำ ทดสอบสร้างออเดอร์ราคา ฿1 ได้สำเร็จ
3. **API แอดมินไม่มีการตรวจสิทธิ์** (`src/app/api/admin/*`)
   ใครก็ดูออเดอร์ทั้งหมด อนุมัติ/ปฏิเสธออเดอร์ เพิ่มหรือลบสินค้าได้ ระบบสร้าง token ตอนล็อกอินแต่ไม่เคยนำไปตรวจ และถ้าไม่ได้ตั้ง `ADMIN_PASSWORD` รหัสผ่านจะเป็น `admin1234`
4. **ดาวน์โหลดได้โดยไม่ต้องมี token** (`src/app/api/download/[orderId]/[productId]/route.ts`)
   ระบบตรวจลายเซ็น HMAC เฉพาะตอนที่ส่ง `token` มาด้วย ถ้าไม่ส่งก็ได้ไฟล์ PDF (HTTP 200) และถ้าไม่ได้ตั้ง `DOWNLOAD_SECRET` จะใช้ค่าลับที่เขียนไว้ในโค้ด
5. **ข้อมูลลูกค้ารั่ว** (`src/lib/ordersStore.ts` → `findOrdersByContact`)
   การค้นหาใช้ `includes` ทั้งสองทาง ค้นด้วย `q=0` ก็เห็นออเดอร์ของคนอื่นพร้อมเบอร์โทรและเลขออเดอร์ ซึ่งนำไปดาวน์โหลดไฟล์ต่อได้
   นอกจากนี้เลขออเดอร์สุ่มแค่ 4 หลัก (`CP-YYYYMMDD-XXXX`) เดาได้ง่าย

## ปัญหาโครงสร้าง (ทำให้ใช้งานจริงบน Vercel ไม่ได้)

6. **ข้อมูลออเดอร์และสินค้าเก็บไว้ในหน่วยความจำ (`globalThis`)** บน Vercel (serverless) ข้อมูลจะหายเมื่อเซิร์ฟเวอร์รีสตาร์ต และแต่ละ instance ไม่เห็นข้อมูลของกันและกัน
7. **สินค้าที่แอดมินเพิ่มจะไม่ขึ้นหน้าเว็บ** เพราะหน้าแรก (`src/app/page.tsx`) และหน้าสินค้า (`src/app/products/[slug]/page.tsx`) อ่านจาก `MOCK_PRODUCTS` ตรง ๆ ไม่ได้อ่านจาก `productsStore`
8. **PDF ที่ส่งให้ลูกค้าเป็นไฟล์ที่ระบบสร้างขึ้นเอง ไม่ใช่ไฟล์ใบงานจริง** (`generateMasterA4Pdf`) ยังไม่มีระบบอัปโหลดหรือดึงไฟล์ PDF จริงจาก Storage
9. **ออเดอร์ตัวอย่าง (seed) ติดไปกับโค้ด production** และหน้า `/downloads/CP-20261105-00x` ถูก prerender เป็นหน้า static ไว้แล้ว
10. **ไลบรารี `sharp` ไม่ได้ประกาศใน `package.json`** ตอนนี้ใช้ได้เพราะติดมากับ Next.js แบบ transitive ควรประกาศให้ชัดเจน

## ลำดับงานที่แนะนำ

1. เชื่อม Supabase จริงสำหรับตาราง orders, products, verified_slips และ Storage ไฟล์ PDF แทน in-memory store
2. ให้ server คำนวณราคาเองจาก `productId` ไม่รับยอดจาก client
3. โหมดฟรี: ตั้งออเดอร์เป็น `PENDING_REVIEW` แล้วรอแอดมินอนุมัติ ห้ามเปลี่ยนเป็น `PAID` อัตโนมัติ และให้ EasySlip ทำงานแบบ fail-closed
4. ตรวจสิทธิ์ทุก API แอดมิน (เช่น session cookie แบบ httpOnly ที่เซ็นด้วย secret) และบังคับให้ตั้ง `ADMIN_PASSWORD` และ `DOWNLOAD_SECRET`
5. บังคับใช้ signed token ทุกครั้งที่ดาวน์โหลด ค้นหาออเดอร์ด้วยการเทียบแบบตรงตัวเท่านั้น และสร้างเลขออเดอร์แบบสุ่มยาว
6. ให้หน้าเว็บอ่านสินค้าจากฐานข้อมูล ลบ seed ออกจาก production แก้ eslint error และเพิ่ม `!.env.example` ใน `.gitignore`
7. แก้ `docs/STATUS.md` ให้ตรงกับสถานะจริง
